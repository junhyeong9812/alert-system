# SY-03. Dead man's switch (감시자 감시)

> **상태**: P1 · **범주**: 시스템 (메타) · **대상 실패**: F7 · **id 의존도**: 없음

## 한 줄 요약
알림 경로가 정상이면 **항상 울리는 알림(Watchdog)**을 계속 보내게 하고, 알림 경로 **바깥**의 감시자가 그 신호가 끊기면 경보를 낸다. "알림이 오지 않음 = 이상"이라는 역전된 논리다.

## 핵심 아이디어
- 알림 시스템이 죽으면 모든 실패가 **조용해지고, 조용함은 정상과 구분되지 않는다.** 그래서 정상 상태를 능동적 신호로 만든다.
- 체인 전체를 통과하는 heartbeat:
  `Prometheus 규칙 평가 → Alertmanager 라우팅 → (선택) notification-service → 외부 감시자`
  어느 고리가 끊겨도 heartbeat가 멈춘다.
- 외부 감시자는 **독립된 실패 영역**에 있어야 한다. 실무에서는 Healthchecks.io, Dead Man's Snitch, Grafana OnCall 같은 외부 SaaS. 로컬 실험에서는 별도 컨테이너로 흉내 낸다.
- 감시자의 경보는 **알림 서비스를 거치지 않고** 채널로 직접 보낸다.

## 전체 구조

```
 [메타 경로]
 ┌────────────┐  Watchdog: vector(1) (항상 firing)
 │ Prometheus │────────────────────────┐
 └────────────┘                        ▼
                               ┌──────────────┐ route: alertname=Watchdog
                               │ Alertmanager │ repeat_interval: 1m
                               └──────┬───────┘
                                      │ webhook (1분마다)
             ┌────────────────────────┴───────────────────────┐
             ▼ 변형 1: AM 직접                                 ▼ 변형 2: 알림 서비스 경유
   ┌───────────────────┐                         ┌──────────────────────────────┐
   │ dead-man-switch   │◀── ping ────────────────│ notification-service          │
   │ (독립 컨테이너)    │                         │  Watchdog 수신 → Notifier 통과 │
   │  last_ping 기록    │                         │  → dead-man-switch ping        │
   │  3분 무응답 → 경보 │                         └──────────────────────────────┘
   └────────┬──────────┘                            (알림 서비스의 발송 경로까지 검증)
            │ SMTP 직접 (알림 서비스 우회)
            ▼
         Mailpit   "[CRITICAL] 알림 파이프라인 heartbeat 끊김 (마지막: 14:02:10)"

 추가 heartbeat 대상 (같은 감시자에 각각 등록):
   - Saga 워치독 스케줄러 (FL-02)
   - Reconciler 마지막 성공 (FL-05)
   - outbox relay 루프 (SG-02)
```

### 변형 1 vs 2
| | 변형 1 (AM 직접) | 변형 2 (알림 서비스 경유) |
|---|---|---|
| 검증 범위 | Prometheus + Alertmanager | + 알림 서비스 발송 경로 |
| 알림 서비스 다운 감지 | 못 함 (SY-01/02에 맡김) | 함 |
| 오탐 원인 | 적음 | 알림 서비스 일시 지연에도 반응 |

## 동작 흐름

| 상황 | 결과 |
|------|------|
| Prometheus 다운 | Watchdog 평가 중단 → ping 중단 → 3분 후 경보 |
| Alertmanager 다운 | ping 중단 → 경보 |
| 알림 서비스 다운 | 변형 2에서만 경보 |
| Slack 장애 (채널) | heartbeat는 Slack을 거치지 않음 → 감지 안 됨 → 알림 서비스의 DLQ 메트릭(SY-01) 담당 |
| 감시자 자신 다운 | **이 프로젝트 범위 밖** — 실무에서는 외부 SaaS로 실패 영역 분리 |

## 보장 속성
- 감지 지연: 무응답 임계(3분)
- 감시 범위: heartbeat가 통과하는 체인 전체
- 비용: 매우 낮음 (1분 1회 요청)

## 책임 경계 (DDD)
- 플랫폼팀 소유. 다른 모든 범주가 의존하는 기반.
- 감시자는 시스템의 **어떤 컴포넌트와도 실패를 공유하면 안 된다**(같은 호스트·네트워크·채널 회피). 로컬 실험은 이 원칙을 완전히 지킬 수 없음을 한계로 기록한다.

## 트레이드오프

| 장점 | 비용 |
|------|------|
| F7을 잡는 유일한 수단 | 감시자를 외부에 둬야 의미 있음 (실무: SaaS 비용) |
| 구현·운영 비용 매우 낮음 | 경로 지연에 따른 오탐 가능 |
| 체인 전체를 한 번에 검증 | 원인은 모름 — "어딘가 끊겼다"만 앎 |
